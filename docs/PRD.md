# PRD — hapora

## 产品目标

让本机的 Typora 进入「已激活」状态，并且**只用一条命令、不引入任何常驻组件**。

## 用户与使用场景

- 目标用户：在本机长期使用 Typora 的开发者（Windows / macOS arm64 / 桌面 Linux）。
- 典型场景：
  1. 上游许可证失效 / 设备被反激活后，一条命令恢复可用；
  2. 换机、重装 Typora 后，一条命令重新打补丁；
  3. 想知道 Typora 到底怎么校验许可证的人，直接读研究报告。

## 核心问题

Typora 两端是**不同的程序，激活链路也不同**：

- **Windows / Linux（Electron 版）**三层串联，缺一层都不成立：
  1. **本地解密**：注册表里的密文必须能用内置公钥解开；
  2. **在线续期**：解密通过后还会向服务端续期，失败就把本地状态打回未激活；
  3. **自校验**：程序启动 1 秒后会校验自身入口文件的 sha256，被改过就直接退出。
  因此「改注册表」「改 hosts 指向本地服务器」这些单点手法在这个版本上都活不下来：
  第 3 层会拒绝被改动的文件，而第 2 层没有真实服务端就无法通过。
- **macOS（原生版）**两层：
  1. **启动判定**：只要求许可证记录字典里 `email` 与 `license` 键存在（不校验内容、不验签、
     不做指纹比对——序列号校验只发生在用户手动输码时）；
  2. **续期窗口**：客户端仅在 `lastTry` 距今超出 1–12 小时（或版本升级首启）时才向服务端续期，
     服务器明确拒绝（`success=false`）会把记录清空（unfill）。
  因此合法记录文件可以在本地完整构造；要长期稳定，要么让续期落在窗口内不发生，
  要么使用真实有效的序列号让续期成功。

## 功能及其意义

| 功能 | 解决什么 | 为什么需要 |
|------|----------|------------|
| `pnpm hack` 一条命令完成 | 备份、注入/伪造、写许可证、打包、验收的编排 | 用户要的是一个动作，不是一堆散装脚本 |
| 定位不依赖固定安装路径 | 装在 D 盘 / 绿色目录 / 非标准位置也能被找到 | 「换了个位置就找不到」是纯粹的使用障碍 |
| 平台差异下沉到 `src/platform/` | 同一套 CLI 在三个平台复用 | 随平台变的东西收敛到一处，编排按能力位分支（见 ADR-010、ADR-011） |
| 备份 + `--restore` | 可回滚 | 会覆盖目标文件（asar 或许可证记录），必须能退回去 |
| 入口名从包内 `main` 读取（asar 路线） | 不把某个 Typora 版本的文件名写死 | 换版本不该改代码 |
| 自校验放行（读取层 + 哈希层双保险，asar 路线） | 让被改过的入口文件仍能通过 sha256 校验 | 不改这一层，程序启动 1 秒后自杀 |
| 许可证解密接管（asar 路线） | 让本地校验通过 | 没有服务端私钥，只能接管返回值 |
| 续期响应接管（asar 路线） | 让状态不被服务端打回 | 假的许可证在服务端一定失败 |
| 更新检查接管（asar 路线） | 不会因为更新把补丁覆盖掉 / 不再弹更新 | 更新会替换 app.asar，补丁随之失效 |
| macOS 伪造许可证记录文件（记录路线） | 原生版没有可注入的入口 | 记录格式可本地完全复现；不动安装包 ⇒ 无提权、不破坏签名、升级免疫 |
| 续期窗口规避（记录路线） | 让状态不被服务端打回 | 伪造记录把 `lastTry` 设在客户端不发起续期的窗口内 |
| 默认自动验收 + 失败自动回滚 | 换版本后「不兼容」表现为安全失败而非坏状态 | 让「跨版本可用」有客观判据，而不是靠运气 |
| `.env` 自定义邮箱与序列号 | 许可证信息可换成自己的 | 伪造的身份信息不该写死在代码里 |
| 逆向研究报告 | 讲清机制与每个结论的证据 | 换版本时能照着重新定位，而不是重来一遍 |

## 功能之间的关系

- asar 路线：备份是注入的前置；注入后必须立刻写许可证，否则启动时读到的仍是空许可证
  （Windows 上是空 `SLicense`）。自校验放行是「让程序能活到读完许可证」的前提；
  许可证接管是「活下来之后是已激活」的前提；续期接管是「一直是已激活」的前提。三者串联。
- 记录路线：备份记录是伪造的前置；伪造记录本身同时承担「启动判定通过」与「续期不发起」
  两个职责（`email`/`license` 键 + `lastTry` 窗口），没有可注入的中间层。
- 自动验收不改变任何状态，只读平台验收信号做判定（Windows 日志 / macOS 记录状态）；
  判定为「可归因失败」时才触发回滚，因此它是「跨版本可用」这一目标的执行者，而不是附加功能。
- `.env` 只影响伪造里的两个展示值，不影响任何判定逻辑。

## 范围与非目标

- 范围内：
  - 单命令激活 / 回滚 / 状态查询 / 自动验收 / 失败回滚。
  - 上述各接管点（asar 路线）与记录伪造（macOS）的实现。
  - 不写死 Typora 版本相关常量：入口名取自包内 `package.json`（asar 路线），
    bundle id / 可执行名取自 `Info.plist`（macOS），自校验基准打包时现算。
  - 面向 Typora `1.14.10` / Electron `42.2.0`（Windows）与原生 `1.14.5-dev`（macOS arm64）的实测与文档。
  - 平台层：Windows 与 macOS（arm64）已完成并在真机验收；桌面 Linux 的定位 / 进程 / 启动已实现，
    **许可证存储待实证后补齐**，在补齐之前显式失败（见 ADR-010）。
- 范围外：
  - 网关、代理、hosts、DNS 等网络层拦截手段。
  - 修改 V8 字节码 `atom.compiled.dist.jsc`。
  - AppImage、移动端、Windows 以外的非桌面发行版。
  - 把补丁做成对任意 Typora 版本「保证可用」——只能做到不兼容时安全失败。
  - GUI、常驻服务、自动更新本补丁。
