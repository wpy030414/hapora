# PRD — hapora

## 产品目标

让本机的 Typora 进入「已激活」状态，并且**只用一条命令、不引入任何常驻组件**。

## 用户与使用场景

- 目标用户：在本机长期使用 Typora 的开发者（Windows）。
- 典型场景：
  1. 上游许可证失效 / 设备被反激活后，一条命令恢复可用；
  2. 换机、重装 Typora 后，一条命令重新打补丁；
  3. 想知道 Typora 到底怎么校验许可证的人，直接读研究报告。

## 核心问题

Typora 的激活链路有三层，缺一层都不成立：

1. **本地解密**：注册表里的密文必须能用内置公钥解开；
2. **在线续期**：解密通过后还会向服务端续期，失败就把本地状态打回未激活；
3. **自校验**：程序启动 1 秒后会校验自身入口文件的 sha256，被改过就直接退出。

因此「改注册表」「改 hosts 指向本地服务器」这些单点手法在这个版本上都活不下来：
第 3 层会拒绝被改动的文件，而第 2 层没有真实服务端就无法通过。

## 功能及其意义

| 功能 | 解决什么 | 为什么需要 |
|------|----------|------------|
| `pnpm hack` 一条命令完成 | 备份、注入、写注册表、打包、验收的编排 | 用户要的是一个动作，不是一堆散装脚本 |
| 备份 + `--restore` | 可回滚 | 会覆盖程序目录里的文件，必须能退回去 |
| 入口名从包内 `main` 读取 | 不把某个 Typora 版本的文件名写死 | 换版本不该改代码 |
| 自校验放行（读取层 + 哈希层双保险） | 让被改过的入口文件仍能通过 sha256 校验 | 不改这一层，程序启动 1 秒后自杀 |
| 许可证解密接管 | 让本地校验通过 | 没有服务端私钥，只能接管返回值 |
| 续期响应接管 | 让状态不被服务端打回 | 假的许可证在服务端一定失败 |
| 更新检查接管 | 不会因为更新把补丁覆盖掉 / 不再弹更新 | 更新会替换 app.asar，补丁随之失效 |
| 默认自动验收 + 失败自动回滚 | 换版本后「不兼容」表现为安全失败而非坏包 | 让「跨版本可用」有客观判据，而不是靠运气 |
| `.env` 自定义邮箱与序列号 | 许可证信息可换成自己的 | 伪造载荷里的身份信息不该写死在代码里 |
| 逆向研究报告 | 讲清机制与每个结论的证据 | 换版本时能照着重新定位，而不是重来一遍 |

## 功能之间的关系

- 备份是注入的前置；注入后必须立刻写注册表，否则启动时读到的仍是空 `SLicense`。
- 自校验放行是「让程序能活到读完许可证」的前提；许可证接管是「活下来之后是已激活」的前提；
  续期接管是「一直是已激活」的前提。三者是串联的。
- 自动验收不改变任何状态，只读 `typora.log` 做判定；判定为「补丁导致失败」时才触发回滚，
  因此它是「跨版本可用」这一目标的执行者，而不是附加功能。
- `.env` 只影响伪造载荷里的两个字段值，不影响任何判定逻辑。

## 范围与非目标

- 范围内：
  - 单命令激活 / 回滚 / 状态查询 / 自动验收 / 失败回滚。
  - 上述三个接管点的实现。
  - 不写死 Typora 版本相关常量：入口名取自包内 `package.json`，自校验基准打包时现算。
  - 面向 Typora `1.14.10` / Electron `42.2.0` 的实测与文档。
- 范围外：
  - 网关、代理、hosts、DNS 等网络层拦截手段。
  - 修改 V8 字节码 `atom.compiled.dist.jsc`。
  - 跨平台；把补丁做成对任意 Typora 版本「保证可用」——只能做到不兼容时安全失败。
  - GUI、常驻服务、自动更新本补丁。
